# _merge-01-02-03 - Preview de planeta por receta y payload de triangulos

## Regla de validacion y workarounds

Cada validacion ejecutable debe correr solo en el contexto definido por este documento.

No se deben anadir `if/else` defensivos, ramas alternativas, fallbacks o workarounds para ejecutar una validacion fuera de su contexto definido.

Si una validacion falla por contexto incorrecto, debe fallar de forma directa y diagnostica. Si existe una alternativa tecnica para rodear el fallo, primero se pregunta si ese workaround es deseado y despues se documenta la decision.

## Objetivo

Crear un objeto tecnico separado del Lab para probar un planeta esferico generado desde:

```text
PlanetRecipe
PlanetPlacement/frame derivado del Transform del objeto
IsoLevel desde PlanetRecipe
requestedTrianglePayload
payload de mesh
```

El objetivo practico es poder probar cargas visuales tipo:

```text
30k triangulos
130k triangulos
500k triangulos
750k triangulos
1M triangulos
2M triangulos
5M triangulos
```

como se hacia antes con Shader Graph, pero ahora usando la base propia del proyecto:

```text
receta -> WorldRadius derivado -> mesh esferico pintado -> Release
```

No se busca cerrar un sistema final de planeta, ni medir memoria, ni ejecutar smoke tests. Se busca ver una esfera del tamano derivado de la receta, con un numero real de triangulos calculado desde un payload pedido de triangulos, y poder liberarla.

Regla central:

```text
La geometria visible de este preview es una isosfera.
El IsoLevel sale de PlanetRecipe.
El payload pide un numero de triangulos.
El sistema deriva una frecuencia geodesica entera y muestra el triangleCount real resultante.
```

## Formula de triangulos

La geometria inicial sera una isosfera generada desde un icosaedro base:

```text
20 triangulos base.
Cada triangulo base se subdivide con una frecuencia geodesica entera.
Cada subpunto se proyecta a la esfera.
```

Formula:

```text
geodesicFrequency = round(sqrt(requestedTrianglePayload / 20))
triangleCount = 20 * geodesicFrequency^2
```

El Inspector debe mostrar:

```text
requested triangles: payload pedido
icosphere frequency: frecuencia geodesica derivada
triangles: 20 * frequency^2
```

Regla:

```text
El payload pedido no promete exactitud perfecta.
El numero real es el que cae de la frecuencia entera de la isosfera.
El usuario puede probar payloads distintos dentro del mismo nivel de receta.
El nivel no se deriva automaticamente del payload.
```

## Flujo funcional

Flujo minimo:

```text
1. Abrir la escena tecnica.
2. Seleccionar el GameObject PlanetRecipePayloadPreview.
3. Elegir preset o escribir requestedTrianglePayload.
4. Ver triangles derivado en Inspector.
5. Pulsar Generate.
6. Ver el planeta esferico pintado.
7. Cambiar preset si se quiere.
8. Pulsar Generate otra vez para regenerar.
9. Pulsar Release para limpiar el mesh.
```

Reglas:

```text
Generate no se ejecuta en Awake.
Generate no se ejecuta en Update.
Generate no se ejecuta automaticamente al cambiar valores de Inspector.
Release puede llamarse dos veces.
OnDisable/OnDestroy pueden llamar Release como red de seguridad.
```

## Gestion de RAM

Reglas:

```text
No generar por frame.
No regenerar automaticamente al editar requestedTrianglePayload.
No usar LINQ en la generacion.
No usar ToArray en caminos repetidos si se puede evitar.
Preasignar listas o arrays con capacidad calculada.
```

Primera implementacion aceptada:

```text
List<Vector3> con capacidad exacta.
List<int> con capacidad exacta.
List<Color32> con capacidad exacta.
Mesh.SetVertices.
Mesh.SetTriangles.
Mesh.SetColors.
```

Si el payload 1M genera demasiado coste o GC, se ajusta despues hacia:

```text
arrays preasignados.
NativeArray.
Mesh.SetVertexBufferData.
Mesh.SetIndexBufferData.
```

No se implementa esa optimizacion por defecto si la primera version sirve para probar visualmente.

```text

```
