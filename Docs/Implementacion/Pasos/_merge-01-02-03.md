# _merge-01-02-03 - Preview de planeta por receta y payload de triangulos

## Regla de validacion y workarounds

Cada validacion ejecutable debe correr solo en el contexto definido por este documento.

No se deben anadir `if/else` defensivos, ramas alternativas, fallbacks o workarounds para ejecutar una validacion fuera de su contexto definido.

Si una validacion falla por contexto incorrecto, debe fallar de forma directa y diagnostica. Si existe una alternativa tecnica para rodear el fallo, primero se pregunta si ese workaround es deseado y despues se documenta la decision.

## Objetivo

Crear un objeto tecnico separado del Lab para probar un planeta esferico generado desde:

```text
PlanetRecipe
PlanetPlacement derivado del Transform del objeto
faceResolution
payload de mesh
```

El objetivo practico es poder probar cargas visuales tipo:

```text
126k triangulos
250k triangulos
500k triangulos
1M triangulos
```

como se hacia antes con Shader Graph, pero ahora usando la base propia del proyecto:

```text
receta -> WorldRadius derivado -> mesh esferico pintado -> Release
```

No se busca cerrar un sistema final de planeta, ni medir memoria, ni ejecutar smoke tests. Se busca ver una esfera del tamano derivado de la receta, con un numero real de triangulos calculado desde `faceResolution`, y poder liberarla.

Regla central:

```text
El numero real de triangulos se deriva de faceResolution.
El Inspector muestra al lado el triangleCount resultante.
```

## Decision CPU Mesh vs Compute Shader

Decision para este merge:

```text
La esfera se genera como Mesh CPU.
No se usa Compute Shader para crear triangulos.
```

Motivo:

```text
02 solo cerro el pipeline compute minimo y la disciplina de recursos.
02 no cerro triangulacion GPU, append buffers, draw indirect ni payload de triangulos.
Usar compute aqui mezclaria este merge con 06_Forma_Planeta_GPU y 08_Payload_Triangulos.
```

La comparativa entre CPU mesh, compute shader, draw indirect o payload GPU queda para documentos futuros.

Este merge debe responder una pregunta mas simple:

```text
Cuantos triangulos puede mover visualmente una esfera runtime generada desde receta antes de que nos moleste?
```

## Formula de triangulos

La geometria inicial sera una cube-sphere:

```text
6 caras de cubo.
Cada cara se subdivide en faceResolution x faceResolution quads.
Cada quad produce 2 triangulos.
```

Formula:

```text
triangleCount = 6 * faceResolution * faceResolution * 2
triangleCount = 12 * faceResolution^2
```

El Inspector debe mostrar:

```text
faceResolution: N
triangles: 12 * N * N
```

Regla:

```text
No se introduce targetTriangleBudget en esta fase.
No se promete un numero arbitrario exacto de triangulos.
Se elige faceResolution y se muestra el numero real derivado.
```

## Flujo funcional

Flujo minimo:

```text
1. Abrir la escena tecnica.
2. Seleccionar el GameObject PlanetRecipePayloadPreview.
3. Elegir preset o escribir faceResolution.
4. Ver triangles derivado en Inspector.
5. Pulsar Generate.
6. Ver el planeta esferico pintado.
7. Cambiar preset si se quiere.
8. Pulsar Generate otra vez para regenerar.
9. Pulsar Release para limpiar el mesh.
```

Reglas:

```text
Generate no se ejecuta en Awake.
Generate no se ejecuta en Update.
Generate no se ejecuta automaticamente al cambiar valores de Inspector.
Release puede llamarse dos veces.
OnDisable/OnDestroy pueden llamar Release como red de seguridad.
```

## Gestion de RAM

Reglas:

```text
No generar por frame.
No regenerar automaticamente al editar faceResolution.
No usar LINQ en la generacion.
No usar ToArray en caminos repetidos si se puede evitar.
Preasignar listas o arrays con capacidad calculada.
```

Primera implementacion aceptada:

```text
List<Vector3> con capacidad exacta.
List<int> con capacidad exacta.
List<Color32> con capacidad exacta.
Mesh.SetVertices.
Mesh.SetTriangles.
Mesh.SetColors.
```

Si el payload 1M genera demasiado coste o GC, se ajusta despues hacia:

```text
arrays preasignados.
NativeArray.
Mesh.SetVertexBufferData.
Mesh.SetIndexBufferData.
```

No se implementa esa optimizacion por defecto si la primera version sirve para probar visualmente.

